본 문서는 파티클 시스템의 대한 연산 부하를 줄이기 위해 도입할 **빌보드(Billboard) 렌더링 기법**을 제시하고, **해당 방식의 채택 배경 및 구현 메커니즘을 기술**하기 위해 작성되었습니다.

# 빌보드 정렬 방식

본 프로젝트에서는 빌보드 정렬 방식으로 **3D 방식**을 채택하였습니다.

해당 정렬 방식은 **3D 월드 공간 내에 빌보드를 위치시킨 뒤 카메라를 바라보도록 실시간 정렬**하는 방식입니다.

**3D 방식**을 채택한 이유는 다음과 같습니다.

- **3D 공간 내의 지형지물과의 공간적 통합**
   3D 방식은 2D 스크린 정렬 방식과 달리 **빌보드를 실제 3D 월드 공간의 좌표를 가진 메쉬 형태로 배치**하므로, GPU의 **깊이 버퍼 연산에 정상적으로 참여**합니다.
   덕분에 바위나 벽 같은 장애물 뒤에 파티클이 가려지는 차폐 처리가 자연스럽게 이루어지며, 3D 월드 공간 내에서 공간적인 통합을 이룰 수 있습니다.

- **카메라 움직임에 따른 원근 표현**
  3D 방식을 사용하면 파티클이 월드 공간에 메쉬 형태로 고정된 채, **카메라의 각도와 위치 변화에 따라 실시간으로 정렬**되므로, 카메라가 이동할 때 3D 공간의 **원근 분할과 거리감에 따른 왜곡을 자연스럽게 반영**할 수 있습니다.

# 연산 주체에 따른 빌보드 구현 매커니즘

빌보드의 월드 위치에 대한 연산 주체가 CPU인지, GPU인지에 따라 **빌보드 렌더링 시스템의 구현 방식**도 달라져야 합니다. 이에 각 파티클 시스템에 대한 빌보드 구현 매커니즘을 구상하였습니다.
## ① CPU 기반 파티클 시스템

CPU 기반 파티클 시스템에서는 **파티클의 생성, 수명, 속도 및 중력 시뮬레이션 등의 물리 연산을 모두 CPU가 담당**합니다.

따라서 **CPU**가 파티클의 월드 위치 정보를 계산하여 **인스턴스 버퍼 형태**로 GPU에 전송합니다.

빌보드의 회전 행렬 연산은 **GPU의 정점 셰이더 단계**에서 뷰 변환 행렬을 활용해 처리하도록 구현할 예정입니다.

## ② GPU 기반 파티클 시스템

GPU 기반 파티클 시스템에서는 **파티클에 대한 위치 연산을 GPU의 컴퓨트 셰이더가 담당**합니다.

따라서 매 프레임마다 CPU에서 GPU로 파티클 위치 데이터를 전송할 필요가 없으며, GPU 내부 메모리(VRAM)의 **구조화된 버퍼에 직접 파티클의 위치를 업데이트**합니다.

빌보드의 회전 행렬 연산은 CPU 기반 파티클 시스템과 동일하게 **GPU의 정점 셰이더 단계**에서 뷰 변환 행렬을 활용해 처리하도록 구현할 예정입니다.
